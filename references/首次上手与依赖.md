# 首次上手和分阶段检查

用户已安装或明确指定本技能后，直接在自己的本地工作目录中调用；不需要作者的完整工作文件夹、根目录AGENTS.md或隐藏文件操作。先从当前SKILL.md的位置确定SKILL_ROOT，再确定独立的WORKSPACE。所有包内路径相对SKILL_ROOT；脚本用绝对路径执行，--workspace和输出路径指向WORKSPACE。先接收已经给出的素材和需求；尚无素材就只收材料，不先做环境问卷。

技能目录只存方法、脚本和默认配置，不保存用户姓名、偏好、素材或任务。用户已有工作目录优先采用；未给目录时在当前可写工作区创建本条目录并自然告知，无本地可写工作区才问一次位置。两个不同工作目录分别有自己的.video-agent/session.json，不相互沿用身份、暂停状态或交付。需要跨目录沿用偏好时，须有本人明确指示。

## Codex首次连接ChatCut

本版主入口是Codex桌面版，兼顾Mac与原生Windows。先接收本次素材与目的；缺少剪辑软件时说明：“这项skill保存剪辑方法，实际时间线由ChatCut Desktop制作，完整效果与工程交接还要剪映。接下来我带你把当前缺的连接做好。”不能只说“缺少依赖”或让用户理解MCP配置。

1. 先只读识别本机软件、Codex可用工具和已有连接，不要求重装已有软件。若缺ChatCut Desktop，提供[官方下载与安装说明](https://chatcut.io/docs/desktop-app)：网页登录后从头像的Desktop App选择本机系统安装包；Mac选择对应芯片，Windows运行安装程序。需要用户完成系统提示时，一次只给当前动作。
2. 安装后打开ChatCut Desktop并登录。然后打开或新建本任务专用项目，保持Desktop运行；不能操作其他正在制作的项目。
3. Codex实际发现本地Desktop工具并读取该项目；若未连上，先按[官方本地连接说明](https://chatcut.io/docs/desktop-app#let-an-external-desktop-agent-control-chatcut-desktop-through-mcp)查看连接状态和Reconnect。工具仍缺失时保存原错，按当前官方路径处理；确需新会话时一次说明恢复位置，不让用户从头填资料，不擅改全局配置。
4. 已装的ChatCut Agent Plugin可能连接云端编辑器，[插件连接](https://chatcut.io/docs/agent-plugin)不会自动创建Desktop本地连接。先辨认当前接口实际控制的项目，不能因为插件工具可见就声称本地剪映交接已就绪。
5. 需要完整剪映工程时，检查用户本机剪映与实际交接入口；先以含本次字幕、效果和动画的小样验证。读取项目成功后，自然告诉用户“连接好了，现在可以继续处理这条素材”。记录已安装、已登录、可读项目、可编辑和可交付各自的证据。

本版不承诺Claude Code、NewMax、WorkBuddy开箱即用；遇到这些宿主给出当前未验证范围，不照搬Codex配置。不要以检测为由转写未被指定的教程或调用配音。转写/生成前确认实际处理的是本次指定素材，并按实际账号说明联网、额度和用户需要确认的动作；不承诺免费或另行索取API key。

## 实际检查

1. 按[双系统使用](双系统使用.md)识别执行端系统，再定位其提供的Python/工具运行时；包内脚本要求Python3.9及以上。Mac与原生Windows共用本技能，Windows使用PowerShell和Windows解释器，不照搬`python3`、`.app`或Mac字体/草稿路径。找不到时给出这一项明确缺口，不把所有软件都要求用户重装。项目路径由本次打开的文件夹确定，不能沿用作者电脑路径。
2. 运行`scripts/doctor.py --workspace '<本项目>' --stage content --source '<已有原片>' --report '<本项目>/.video-agent/preflight.json'`。脚本只读观察Python、可选Pillow、FFmpeg/FFprobe、软件安装版本、字体、素材和实际卷空间。找到了文件/软件不等于连接可用、预设生效或质量通过。
3. 从宿主当前工具目录发现ChatCut接口，实际读取目标项目。对约定完整剪映交付的任务，在整条精剪前运行`--stage readiness`：真实检查本次可编辑交接入口、剪映控制和本任务专用草稿范围，不等最后交工程才查。已知不能交接时先说清当前受阻动作，保存原片及已做内容，不让用户完成漫长剪辑后才知道缺口。记录工具调用、对象和观察时间。可用`--capabilities-file`读本项目实际观察回执，必须与`--task-id`匹配，不能复制其他机器或任务的通过状态。
4. 第一条代表小样走一次最终交付路径：专用原生草稿、实际字体/美颜/色彩、小样导出、应用支持的备份及重新导入打开。`--stage preview`要求`native_preview_reopened`及`native_preview_render_checked`的真实证据；它只证明该小样路径，整条交付仍须再次检查同修订。`look`核对字体/效果资源，`delivery`核对最终工程，`review`检查本地媒体工具。下游缺口不阻塞接收原片、转写和保存进度；但不能把未验证的完整路径宣称已可用。保护素材按实际体积预算，交付才加整片导出预算；不足不自动清理。

回执结构为`task_id`及`observations`数组；每项包含`capability`、`status`（passed/failed/not_checked）、`observed_at`和`evidence`。可用能力名见doctor脚本。只有本轮真实调用结果才写passed；脚本仅校验凭证结构，不能认证人工填写内容的真实性。

## 依赖缺失时

- FFmpeg/FFprobe先查宿主运行时、PATH、项目工具目录和已安装ChatCut自带工具，可通过`--ffmpeg/--ffprobe`明确路径；不用作者固定路径，也不自动下载陌生二进制。
- Pillow仅用于测字宽，接收素材和原生剪辑不依赖它。确需时用`scripts/setup_local_dependencies.py --workspace '<本项目>'`先得到本地安装计划，实际安装加`--install`。只创建`.video-agent/runtime/python`及本地缓存，不修改系统Python、全局包、Codex配置、插件或应用。已有环境先检查，不覆盖；失败保留目录和日志。新环境使用其Python重新运行doctor与检查脚本。
- 字体/美颜模型不打包分发。字体文件存在仍要在实际渲染中核对，资源ID和数值存在仍要在新机器复现小样。缺字体提出具体替代样式；不未经同意取消完整默认效果。
- ChatCut连接、剪映控制、动画和配音是宿主能力，不由Python脚本伪造。需要安装/登录/授权时一次只讲当前必要动作，沿官方入口或用户实际界面操作；不承诺免费，不擅自订阅。

## 启动结果

对用户说清“现在能继续什么”和最多一个当前必要动作。完整诊断留项目，避免发一屏工具名称、配置字段或依赖清单。安装/状态、连接/项目读取、资源渲染、成片检查和新用户验收分别记录。

双系统自动化结果见[验证范围](../docs/验证范围.md)；脚本运行不等于另一位用户已完成实际剪辑。Windows本机GUI、软件连接、账户资源和原生交接仍在首次小样核对；Linux/WSL与未测软件版本不冒称通过。

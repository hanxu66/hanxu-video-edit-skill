# 直播回放：切片与卡片式短视频

本地用户化依据为已有直播切片方法与使用者明确补充。输入可以是完整回放或指定区间；不要求作者内部台账、旧已剪状态或个人业务资料。完整回放与选定区间的覆盖范围分别记录，未看全场不能声称已找完全部精彩片段。按[执行标准](剪辑执行标准.md)核验，画面及资源沿[完整默认效果](默认效果与调整.md)。

## 内容与制作

1. 锁定原回放、文件哈希、实际读取范围、源时间码、当前修订；项目外素材先保护工作副本。全场找切片时完成实际覆盖的转写与主题索引，记录已处理/未处理范围。使用者指定区间就直接处理该区间，不强制分析整场。
2. 候选内容卡记录问题、判断、证据、收束与原始时间码。使用者已选定某段就不重复选段问卷。不得截断必要条件，把现场问答、期待或他人经历剪成主讲人的既成结果。一场可以没有合适切片，不凑数量。
3. 每条从原回放建立独立可编辑时间线，记录源时间码→新时间线→编辑目的；删口误、失败尝试、无意义重复和停顿，调序不改变主语、因果、时间及结果强度。不先做扁平母版再拆。多人互动保留必要提问和承接，不机械套单人口播的零停顿规则。
4. 回读内容、剪点、字幕及源时间码；按当前交付范围交接可编辑剪映草稿，实际核对不支持属性。只处理本项目，进度逐条记录，不调用正式台账或自动发布/清理。
5. 既有直播场景默认速度1.2倍，显式用户调整优先。主讲人声音沿完整默认20dB基线，先查素材峰值与已有增益，可能削波时在本条校准并记理由，只直接设一次；其他说话人按实录校准。美颜美体及调色能力保留，按当前人物和光线校准；额头、脸颊泛白或脸部缺少层次时，进入[泛白调色返修](常见问题与局部返修.md#画面泛白与调色)，同时检查PPT白底、图片与文字是否仍清楚。主字幕13号；顶部主题起始18号，可降16/15；姓名/身份起始10/8号。这是剪映单位，其他渲染器按真实字形大小校准，不能把13当像素或借不同单位缩小字幕。
6. 内容锁定后制作同修订封面与实际视频，竖屏技术参数沿完整默认。重新打开最终文件，对照源回放、索引及当前工程复查内容、画面、声音、字幕和时间码。参数配置或导出成功不等于实际审看通过。

## 版式随原回放校准

全屏真人、上PPT下真人、屏幕共享等属于直播画面布局，先看实际源帧，不因同为直播切片就套同一裁剪和文字坐标。PPT已在原片里时保留实际页面，不能把它路由为新生成PPT动画。字幕与主题避开页面关键文字、人物脸部及已知平台遮挡区；先给含长字幕与实际页面切换的代表画面，让用户看实际大小。不能凭本机单帧宣称平台手机安全区已验证。

上PPT下真人的切片，在小样排版和最终导出前实际打开目标平台安全区预览；抖音可用剪映的“安全区 → 抖音预览”，按当前版本实际界面操作。完整标题及阴影与遮挡边界之间应有可见空隙，贴边也要调整；优先下移到可用留白，同时避开PPT与人物动态头顶。顶部标题、主字幕、右侧界面和独立封面分别核对，记录当前原生预览与同修订导出证据，详见[安全区返修](常见问题与局部返修.md#顶部标题与平台安全区)。

用户要求选有画面的课件时，候选记录除时间码和话题外，还要核对讲述期间实际PPT页面含截图、照片或其他有效画面；纯文字页不能冒充符合该要求。此为本任务选段条件，不升级成所有直播都必须排除文字页。不能靠封面有图、后期加图或只看转写证明原回放该时段有图。

按原有字号制作后检查原生实际渲染；长句自动换行或溢出时优先按语义及现有词级时间拆卡，保留原文，不用缩小字号、负字距或删词掩盖问题。封面从本条实际源帧选择适合标题的位置，可按用户要求保留PPT或突出人物；封面选择不回改正片布局。布局适配与可编辑工程交接分别检查，不能把通用工程故障归因于一种直播形态。

## 直播卡片分支

使用者已明确“直播卡片”指回放剪成卡片式短视频。沿上面的真实原声、选段和时间码链制作；不得路由成直播间常驻标题/贴片，也不擅自交成静态图或全文文字卡。

卡片的既有版式、是否保留人物、主题/正文/字幕位置与动态方式尚未在本包找到可核对的原样例；这些是待补的视觉参考，不是否认原Agent已有能力。进入画面制作时先沿使用者给定的既有示例校准代表小样；尚无参考只补这一项，不重新询问已给素材/场景。未确认前不把新设计称为原有默认卡片风格。其余既有可用默认与用户调整继续有效。

批量任务逐条保留源索引、已认可内容、当前修订和交付，暂停、采用及发布分开。所有素材和未采用版本保留，除非使用者另行要求清理。

# 剪辑接续、当前要求与局部返修

下列通用章节来自当前方法；独立用户以本次任务、自己的素材及本地记录执行，不继承维护者私人授权。

## 对象、有效要求与定稿接续

- 开工锁定对象ID、原素材、场景、当前有效修订、本人本次原话、已认可项、反馈与交付目标。旧工程和执行记录只能提供依据，不能覆盖本人本次要求。
- 本人宣布旧版作废或要求修正形式时，重新核实本次类型、范围及仍有效的选择。旧运行记录中的动画数量、版式或“仅局部”等执行判断不能自行升级为本人要求；继承项须能回到实际本人原话与未被撤销的适用范围。没有明确数量时交Skill按语义关系设计，不把旧清单带成固定上限。已明确保留的原声、调色等属性继续有效。
- 本人明确当前版本定稿、不再修改时，锁定其实际文件和版本，停止本条返修，后续讨论／归档不触发制作；将本人采用、仍保留的缺陷与既有技术检查分别记录。不得把本人定稿改写成缺陷已修复或重新检查通过，也不推定已发布，不把当前有效工程与依赖送去失败版本清理。只有新的明确改片要求才恢复制作。
- 交付前的可执行检查与缺陷处理由工作流完成，不把明显可见问题的发现交给本人。只有真正缺失的素材／权限／审美决定或真实听辨缺口需要本人时，先完成本机可做部分，再一次说明具体缺口和最小必要动作；不能把预设复用要求解释成只能由本人恢复。

## 每个大步骤的预读、检查与检查点

1. 每个业务步骤前按总入口读取规则重新读取本Agent、[剪辑执行标准](剪辑执行标准.md)和当前场景Skill文件，再执行本步；不能以本轮早先读过代替。
2. 将本步目标、工具、参数和应产生的证据形成简短清单，同类确定性操作成组执行，不每点一次就截图一次。
3. 做完后再读同一执行标准章节，依实际工程、波形、时间尺或导出物检查。通过后才保存检查点并继续；失败就停在本步。
4. 运行记录写明：步骤、工具、修订、实际值/结果、证据路径或时间码、结论和检查点时间。普通口播按[口播Skill的执行记录](字幕批量质检与执行记录.md)在同一份run中接入九项包装证据、互斥阶段计时及当前剩余容量计划，沿用已有来源和检查结果引用，不额外为每一步建立修订快照或独立回归表。正常制作、流程返工、意外故障分别汇总；正常效率包含流程返工，意外故障单列并保留交付总耗时。本Agent只接收对应范围的结果，不把记录完整或文件检测完成升级为整体交付。局部变化只使受影响项失效，旧工程证据不跨新草稿继承。
   同批连续剪辑时，每条视频分别记录本步预读的Agent、Skill、标准文件及读取时间，完成后的标准复读、核对项、发现的问题和修复后复查；第一条的记录不得复制为第二条的凭证。缺少本条本步的复读或结果仍有问题时，不保存通过检查点，不进入下一步。
5. 同一步内连续点击不重读全文；进入新大步骤、返修、失败重试或恢复断点时重读对应章节。
6. 局部返修仍是一次新执行，不得因为“只改封面／字幕／文字”而跳过第1步。返修前必须从当前场景Skill和剪辑执行标准重新提取本步的位置、安全区、字体、颜色、层级和验收条件，写入本次清单后才能操作。
7. 不得将直播间贴片、顶部常驻标题、小红书图文或其他场景的版式经验带入短视频封面，除非当前场景Skill或使用者当次明确要求。验收时按本次清单逐项回读，不得只检查表情、遮脸或有无字幕就给出`PASS`。

## 异常恢复与操作证据

- 字幕检测先按口播Skill完成配置验证、代表卡探测和全量覆盖；检测器/字体或OCR引擎错误立即停止对应分支并保留失败报告，不路由成全条人工逐卡重试。资源不足只暂停需要新增分配的阶段；继续前按原生导出、副本、重试和临时媒体的完整剩余预算回读。
- 截图、图像分析和OCR用于确认界面状态、字幕/标题/封面、明确画面异常与大步骤检查点；不用它们逐帧验收气口、重复确认有效参数或替代波形和时间尺。
- 工具或电脑控制卡住时立即停止连续点击，先确认最后动作、当前对象和最近检查点。已保存且时间线未变，从当前步继续；结果不确定，只回到最近检查点的当前步。
- 首次回读证明操作无效就进入[口播Skill恢复分支](口播剪辑.md)，按控制失效、应用未响应、资源不足分别处理；不要求先重复失败操作。符合保存与退出条件时最多重启对应软件一次；首次失败10分钟仍未恢复就记录单一真实阻塞，不循环重启或开新方法。重启以应用实际退出、再次启动、正确修订的主窗口可读及保存检查点核对为恢复证据；仅看到进程运行或分享状态小窗口不算恢复，也不能据此推断锁屏或工程丢失。本轮恢复成功只证明可以继续，不证明工具故障已永久修复。
- 动画交接失败按口播Skill第四步的可靠路径接续；恢复后按第五步的工程绑定及参数失效清单接力，只让真实变化项与下游依赖失效。资源检查未通过只阻塞依赖该资源的步骤，不中断可独立执行的内容工作；没有产物变化不扩大重做范围。
- AI因环境无法接收声音时，只跳过实际听辨；可执行的音轨来源、音量字段、波形、时间码和音频流检查照常完成，不反复排障或要求使用者开音量。
- 内容接缝与声音按[剪辑执行标准](剪辑执行标准.md)分别接收结果：短碎片复查未完成不推进交接；已知异常只有编辑记录而无声音结果时，不升级为声音通过。本人反馈否定既有通过结论时立即使对应声音结论及真实下游检查失效，按局部返修链继续；不要求本人重复已确认的结果。

## 返修路由与版本规则

- **归属ChatCut的问题：**内容取舍、重录/重复、语义顺序、上游速度、上游时间线与剪点。只有内容、顺序、素材来源或实际声音画需要变化时，才走`ChatCut返修 → 新ChatCut修订 → 新剪映草稿 → 重做真实失效的下游步骤 → 剪映重新导出`。
- **归属剪映的问题：**下游声音与画面参数、交接后字幕、文字包装、封面和导出设置。直接在剪映当前修订批量或局部修复并重新导出。
- **局部显示与剪点问题不默认重建：**实际声音画不变的字幕显示返修路由到当前可编辑工程；少量局部剪点返修路由到当前最终工程。当前工程可独立修改时，不新建上游工程或草稿。
- **耦合问题按引入位置归属：**气口在ChatCut交接前已错属ChatCut；交接后发现的少量局部气口可在当前可编辑最终工程修正。字幕显示错字不等于内容取舍变化；只有实际声音画或内容选择需要改变时才返回ChatCut重建。
- 每次ChatCut重新交接都创建新修订，不覆盖旧剪映草稿；继承前逐项记录哪些剪映检查点失效、哪些继续有效。
- 局部返修在原运行记录接收实际变化项、继续有效项和证据引用；不强制生成前后两套快照。未变项按其仍有效证据沿用，真实来源、时间线或参数变化使相应检查失效。核对只覆盖已提供的数据，不能据此豁免最终画面与声音结果检查。
- 同一类ChatCut缺陷连续返修两次仍未达标，立即停止工具间来回切换，报告具体的工具/标准阻塞。

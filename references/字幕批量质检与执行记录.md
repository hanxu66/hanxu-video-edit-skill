# 字幕批量质检与执行记录

本文件是[口播剪辑](口播剪辑.md)的工具操作说明。语义、样式、参数和结果判定仍读Skill及[剪辑执行标准](剪辑执行标准.md)。工具只读取用户提供的媒体、字体和证据，写入指定的本地记录；不控制软件、不清理文件、不提交发布状态。

## 调用位置与依赖

由Codex定位当前SKILL_ROOT和用户WORKSPACE，使用已核验的本机Python调用包内scripts，工作目录与所有输出留在WORKSPACE。下方`python3`仅为Mac示意，Windows使用[双系统使用](双系统使用.md)中的实际解释器调用形式。Python3标准库负责记录、容量与文件检查；字宽和像素检查还需Pillow。抽帧、文件探测、完整解码和容器修正使用本机已可用的FFmpeg/FFprobe，可用`--ffmpeg`、`--ffprobe`指定路径；本工具不安装剪辑引擎，不携带字体、人物素材、私人转写、校准样张或运行记录。

## 字幕：文字与时间、几何与字形分开验证

1. ChatCut提供最终保留文字与最终速度下的词头时间。执行者先按完整意思分卡，再用`check_subtitle_width.py`按剪映目标字体测宽，输出计划SRT。不能按固定字数截断，不能让ChatCut的预览字体代替剪映字体。
2. 正式导出时另导出当前剪映原生SRT。`check_subtitle_render.py scan`先逐卡核对计划SRT与原生SRT的文字、数量和真实起止时间（只容许毫秒取整误差），再核对实际成片。文字不一致先处理交接差异，不把OCR当作校正稿。
3. 实际画面检测使用字体校准后的白色静态字幕像素与字形。它核对行数、位置、安全边界、漏显及明显字形差异；手势、麦克风反光或栅格差异可能产生疑点，进入集中复核。语义完整、实际说出的词、音画同步、人物与动画合成及整条实播分别核验。

### 配置与首次验证

沿用字宽配置的字体文件及SHA256、实际像素字号、画幅、安全边界、锚点、余量、缩放和字距，增加`render`对象：

```json
{
  "canvas_height_px": 1920,
  "crop": [0, 1240, 1080, 400],
  "scan_band_px": [90, 310],
  "expected_center_y_px": 200,
  "center_tolerance_px": 8,
  "white_threshold": 220,
  "max_channel_difference": 30,
  "row_min_pixels": 10,
  "row_join_gap": 8,
  "row_min_rows": 6,
  "row_padding": 3,
  "shape_f1_min": 0.98
}
```

这些值仅展示schema，不是其他素材的默认参数。`crop`为成片坐标中的左、上、宽、高；`scan_band_px`和中心纵坐标相对于裁片。用本条原生代表画面确定阈值、字幕带、误差与字形相似度，不能改阈值只为消除当前疑点。`calibration_ref`指向原生字段及校准证据文件，配置必须标记已校准。字体文件SHA、配置、校准证据和检测脚本变化都使旧验证失效。

`samples.json`为列表，每项含`path`、`text`、`expectedLines`；必须包含真实剪映单行及折行样张，至少一个单行项含`wrongText`，用于同字数错词对照。执行：

```bash
python3 "<SKILL_ROOT>/scripts/check_subtitle_render.py" validate --profile render-profile.json --samples samples.json --output validation.json
```

工具验证原生单行正常、原生折行可检出，以及明确标为合成的漏显、水平越界、纵向移位和错词对照。不把合成控制说成真实剪映失败案例，也不把少量校准说成任意字体/背景均可用。当前检测限白色静态字幕、已验证字体及正常缩放/字距；新颜色、动态字幕、不同字距/缩放、字体缺字或字幕带无法分离时，先补相应验证，不能照搬旧配置或交给几百张人工识别兜底。

### 全量扫描与疑点复核

```bash
python3 "<SKILL_ROOT>/scripts/check_subtitle_render.py" scan --video final.mp4 --srt planned.srt --native-srt native.srt --profile render-profile.json --validation validation.json --output-dir caption-qc
```

先探测少量首尾、长短和混排卡，再批量抽取每卡稳定帧。实际视频必须与配置画幅一致、零起点且恒定帧率；时间码取真实帧，不从卡号估时。探测大面积几何失败即停止，避免把检测器错误变成整条逐卡返工。OCR只可作另行验证后的辅助；OCR引擎异常先停该分支，不触发逐卡重试。

产物为`report.json`及带时间戳历史、全卡覆盖清单、带哈希的抽帧缓存和每页12张疑点拼图。退出码0仅为该检测范围完成，1为存在待复核疑点，2为配置/输入/检测失败；错误会覆盖最新报告为失败，旧绿灯不能代表本次。缺帧、抽帧不全、SRT差异、旧配置或字体缺字均不能默认为通过。

人工在拼图中集中复核疑点，必要时打开原始裁片与完整合成画面。确为误报时，将`report.json`的`signature`原样放入复核JSON，每项`reviews`写入`id`、对应`frame_sha256`、`disposition="false_positive"`、具体`note`及可达的`evidence`文件，再执行：

```bash
python3 "<SKILL_ROOT>/scripts/check_subtitle_render.py" scan --video final.mp4 --srt planned.srt --native-srt native.srt --profile render-profile.json --validation validation.json --output-dir caption-qc --reuse-frames --review review.json
```

同一媒体、字幕、配置、校准和检测脚本哈希全部匹配，且全部帧文件及描述匹配，才能复用抽帧；复核还必须绑定同一签名和对应帧哈希。已有视觉复核只在像素文件完全一致时可引用。真实错误回当前可编辑工程局部修复，重导后用新目录检测；新文件不会沿用旧绿灯。静态中点不覆盖入退场、语义、实际听辨与人物/动画遮挡，这些项目保留独立检查证据。

## 包装证据清单与检查点

在当前WORKSPACE的`.video-agent/session.json`内给当前task写入`editingExecution`，不另建第二套状态库。以下`run.json`均指该session文件的实际绝对路径；工具也支持既有独立任务run JSON。`requirements.json`必须显式含九项：`speed`、`voice`、`beauty`、`body`、`grade`、`subtitles`、`identity`、`animation`、`cover`。每项为`{"required":true,"target":实际目标JSON}`；不适用为`{"required":false,"reason":"本次范围依据"}`。目标来自当前Skill与本人范围，不由脚本发明。

```bash
python3 "<SKILL_ROOT>/scripts/manage_video_editing_run.py" init --record run.json --revision r1 --requirements requirements.json
python3 "<SKILL_ROOT>/scripts/manage_video_editing_run.py" verify --record run.json --key beauty --actual actual-beauty.json --evidence native-readback.png --scope '当前实际工程及全部受影响人物片段的原生回读'
python3 "<SKILL_ROOT>/scripts/manage_video_editing_run.py" checklist --record run.json
```

`actual-*.json`是实际重新选中对象后的回读值；每项还要记录作用范围及证据文件SHA。单张截图不能自行证明整轨生效，执行者仍须核对覆盖清单。缺证据、目标不符、证据文件变动都会保留未完成；退出码1不得推进包装门。`packaging_record_complete`只证明记录齐全，不证明截图内容真实，也不替代资源、文件、实播或本人采用。

新建草稿/修订重新初始化；同一草稿的局部变化用`invalidate --record run.json --key subtitles --reason '本轮实际变化'`使受影响项失效，再补验。没有变化的有效检查点保留，禁止清空记录重填假通过。

## 剩余容量预算与文件检查

资源工具优先使用完整计划：

```bash
python3 "<SKILL_ROOT>/scripts/inspect_video_editing_environment.py" --path cache-directory --path export-directory --min-free-gb 5 --budget-plan remaining-capacity.json
```

计划为`{"items":[...],"excluded":{...}}`。每项含唯一`label`、`kind`、已存在的`directory`、`bytes`，或`duration_seconds`、`video_mbps`、`audio_kbps`，可指定正整数`copies`。`native_export`、`container_copy`、`retry_export`、`temporary`四类必须逐一列入，或在`excluded`说明当前剩余阶段为何不需要；不得同时列入又排除。还计入真实需要的动画媒体、交接副本、缓存与校验文件。原生导出需保留、容器修正另生成文件时，两个文件都占容量；重试估算另列，不能只预算交付文件。

已在磁盘的文件已影响实测空闲，不重复追加估算；若列入追踪则标记`already_present=true`及真实`existing_path`。同卷累计一次，各卷分别保留最低余量，不把外接盘空闲算给系统缓存卷，不预支可清理空间、APFS克隆或purgeable空间。纯质检阶段已完成的输出可以有据排除，不能把导出前预算缩成质检预算来获得通过。先检查是否能减少不必要的复制，再按既有清理授权处理；本工具不删除媒体、不降低余量。

成片文件检查：

```bash
python3 "<SKILL_ROOT>/scripts/check_video_export.py" --video native.mp4 --spec export-spec.json --output-dir file-qc
```

`export-spec.json`含当前Skill目标`width`、`height`、`fps`（如`30/1`）、`video_codec`、`audio_codec`、`sample_rate`、`color_space`，已知最终帧数时填`expected_frames`。用户明确要无声作品且文件没有音轨时，`audio_codec`设null；不能为正常有声交付跳过声音。工具读取真实容器与编码流、逐帧时间戳和帧数，完整解码并列黑帧候选。码率及其他未列入的字段仍按Skill回读，不把此检查误称全部参数已验。

仅当原文件只是MOV容器不符、其余检测正确时，可在预算已通过后增加`--remux-to new-final.mp4`：保留原文件，原编码流复制，核对音视频流哈希一致并重新完整解码。目标已存在即拒绝覆盖。缺帧、非恒定帧率或其他参数错误不得靠封装、补帧或改扩展名掩盖，应返回原生导出。修正后的最终文件仍须实际全片播放；黑帧候选需视觉判断，不自动作为错误或忽略。

## 分段计时

```bash
python3 "<SKILL_ROOT>/scripts/manage_video_editing_run.py" timer-start --record run.json --phase chatcut_semantics --category active
python3 "<SKILL_ROOT>/scripts/manage_video_editing_run.py" timer-stop --record run.json
python3 "<SKILL_ROOT>/scripts/manage_video_editing_run.py" summary --record run.json
```

阶段按实际命名，例如ChatCut语义、剪映操作、字幕预检、成片质检、导出。类别为`active`主动操作、`wait`软件/工具或资源等待、`rework`修复已有错误。切换类别/阶段时先停后开，同一时刻只开一个区间，不重叠相加；脚本子进程的机器耗时单列，不叠加成AI主动时间。重启/时钟异常的开放区间保持未验证。未记录的历史时间为未知，不补写0，也不能拿总墙钟时间估算提速百分比。
